# KyoshinShindoPlaceEditor

[简体中文](readme_CN.md) | 日本語

強震モニタ画像の色を取得するピクセル座標を編集する Windows アプリケーションです。**0.0.7.0 では WebView2 + Canvas UI が既定**です。従来の Windows Forms UI も互換モードとして残しています。
この fork は [ingen084 の原版](https://github.com/ingen084/KyoshinShindoPlaceEditor) 0.0.6.0 を基に、簡体字中国語 UI、新形式 JSON 対応、読み込み時の例外対策、公式 CSV ダウンロード、元に戻す操作、選択点の表示補助を追加しています。UI のメニュー名は以下も中国語表記です。

## この fork の変更点

- 地図描画を Canvas、一覧を仮想スクロールに変更。新 UI ではネイティブの観測点行を作成せず、1 点の変更は差分だけを通知します。
- 背景地図を同梱し、リアルタイム画像はタイムアウト付きのバックグラウンド取得に変更。取得失敗時も編集と保存を続けられます。
- UI とエラーメッセージを簡体字中国語化。観測点名・地域名・コードは翻訳しません。
- 強震モニタの背景・地表・地中画像 URL に含まれていた無効な `/new/` を修正。
- `kyoshin-monitor-observation-points` の `intensity-points.json` に対応。旧 PascalCase JSON も引き続き読み書きできます。
- 無効なデータの読み込み失敗時に既存データを保持し、描画で例外が起きてもウィンドウの操作状態を復元。
- K-NET / KiK-net の公式 CSV をアプリ内からダウンロード。現行 11 列と旧 14 列の NIED CSV に対応。
- `Ctrl+Z` による最大 50 操作の取り消し。
- 観測点コードで既存の座標ファイルを結合し、現在の NIED 情報を維持したまま画像座標を追加。
- 1 点の編集で一覧全体を作り直す処理を修正。上下地図の選択連動と OSM 上の観測点選択に対応。
- 選択点の黄色い点滅と、原画像で 3×3 ピクセルの安全枠。**表示・注意喚起のみで、重複配置や保存を禁止しません。**

## 起動と基本操作

新 UI には Windows 10/11、.NET Framework 4.7 以降、Microsoft Edge WebView2 Runtime が必要です。配布版の `Modern`、`runtimes`、WebView2 DLL、従来の DLL と設定ファイルを維持して `KyoshinShindoPlaceEditor.exe` を起動してください。

1. ツールバーの `打开` または `Ctrl+O` で点位ファイルを開きます。
2. 右の一覧から観測点を選び、左上の画像を左クリックして画像座標を設定します。
3. 画像上の既存の点を中クリックすると、対応する観測点を選択できます。
4. 一覧の右クリックメニューから休止状態の切り替えや画像座標のクリアができます。
5. `保存` / `另存为`、または `Ctrl+S` / `Ctrl+Shift+S` で保存します。**変更は自動保存されません。** 終了や別ファイルを開く際は未保存の変更を確認します。

画像・地図は右ドラッグで移動できます。画像を表示範囲外まで動かさないよう注意してください。
`刷新图像` は手動更新で、画像上部の選択欄から地表・地中を切り替えます。検索欄ではコード・観測点名・地域を絞り込めます。一覧では方向キーと Home / End も使えます。

### 従来 UI

旧メニュー、EqWatch インポート、互換性確認には以下を使用します。

```powershell
.\KyoshinShindoPlaceEditor.exe --legacy
```

以下に残る `文件 / 导入 / 视图` のメニュー経路は従来 UI を指します。新 UI ではツールバーの同名ボタンを使います。従来 UI のネイティブ一覧では再描画の遅延が残るため、通常は新 UI を使用してください。

### 2 つの地図の違い

- **左上**: 352×400 ピクセルの強震モニタ画像。ここで編集する値は画像の色を取得する座標であり、緯度経度ではありません。1x～5x の表示倍率に対応します。
- **左下**: 内蔵の静的な OSM 地図。画像座標設定済みの点は緑、未設定は青、休止中は灰、選択点は赤で表示します。点の近く（8 ピクセル以内）を左または中クリックすると最も近い観測点を選択します。新 UI ではホイールで 0.5x～4x に拡大縮小できます。緯度経度の編集とオンライン地図には対応しません。

新 UI の `选点联动定位`（従来 UI の `视图 → 选点时同步定位上下地图`）は既定で有効です。一覧、上画像の中クリック、OSM の点選択に合わせて両地図を選択点へ移動します。`Ctrl+L` または `定位当前站点` で手動移動もできます。連動を無効にした場合も、各地図を右ドラッグで動かせます。
画像座標が未設定の点は下地図だけで位置を確認でき、画像座標を自動推定・設定しません。両図は座標系が異なるため、ドラッグ量そのものは同期しません。

### 点滅と 3×3 安全枠

選択点は 500 ミリ秒ごとに黄色く点滅し、安全枠は点滅せず表示されます。
安全枠は原画像の 3×3 ピクセルで、倍率に合わせて拡大されます。
他の点位がなければ青緑、有効な画像座標が枠内にあれば赤になり、下のステータスバーに件数を表示します。休止中の観測点も判定対象です。

判定には実際の取得座標（新 JSON では `center_point + offset`）を使用します。
**枠は参考表示です。重複する場所への移動・編集・保存も可能です。**

### 元に戻す

ツールバーの `撤销`、`Ctrl+Z`、または従来 UI の `编辑 → 撤销` で最大 50 操作を戻せます。
座標移動・クリア、休止状態の変更、並べ替え、点位ファイルの結合、NIED / EqWatch のインポートに対応し、インポート・結合全体は 1 操作として扱います。
保存後も取り消せますが、ファイルへ反映するには再保存が必要です。
ファイルを正常に開くと履歴を消去し、読み込み失敗時には保持します。表示倍率、選択、ドラッグ、ダウンロードは履歴に入りません。やり直し機能はありません。

## ファイル形式

| 形式 | 開く / 保存 | 注意 |
| --- | --- | --- |
| JSON (`.json`) | 対応 | 新形式と旧 PascalCase 形式 |
| MessagePack (`.mpk`) | 対応 | 原版形式 |
| LZ4 MessagePack (`.mpk.lz4`) | 対応 | 原版形式 |
| エディター独自 CSV (`.csv`) | 対応 | NIED の CSV とは別形式 |
| NIED CSV | 専用インポート | `导入 NIED CSV` を使用 |
| ProtocolBuffers (`.pbf`) | 未対応 | 従来 UI に未実装の選択肢が残っています |
| `.kmop` / `sitepub_all_utf8.csv` | 未対応 | 新形式や Web 用統合 CSV の直接読み込みは未実装 |

### intensity-points.json

小文字のフィールドと `point.center_point` / `point.offset` をそのまま読み込みます。
新形式 JSON を開いて JSON に保存する場合、元の形式、追加フィールド、`sub_region`、未編集の緯度経度の精度を保持します。
移動後の偏差が各軸 -8～7 の範囲なら中心を保持し、範囲外なら新しい中心とゼロ偏差で保存します。
追加情報を保持したい場合は JSON を使ってください。CSV / MessagePack へ変換すると新形式固有の情報は保持されません。

最初は `另存为` で別名の JSON に保存し、内容を確認することを推奨します。

### NIED 情報と既存画像座標の結合

通常の `文件 → 打开` は現在のデータを置き換えます。複数の情報源を合わせる場合は専用メニューを使います。

1. `导入 NIED CSV` で公式 CSV を選びます。K-NET と KiK-net の同時選択も可能です。
2. `合并坐标文件` から、画像座標を持つ `intensity-points.json` または対応するエディター JSON / CSV / MessagePack ファイルを選びます。
3. 結合後、`另存为` で JSON として保存します。

同じコードでは現在の名前・地域・緯度経度・休止状態を保持し、取り込む側の非空画像座標で補完・更新します。空座標で既存座標を消しません。一致しない点は追加します。同コードのネットワーク種別不一致、検証失敗、CSV の読み込み失敗行がある場合は結合全体を拒否し、元データを保持します。

新 JSON の中心・偏差・追加フィールドも保持します。既存の追加フィールドは現在値を優先し、画像座標構造は取り込む非空座標に合わせます。結合は取り消せ、取り込みファイルが保存先に変わることはありません。

### エディター独自 CSV

ヘッダーなしの以下の列順です。未設定の画像 X / Y は空欄です。原版ライブラリの CSV 処理には欠損値や引用符を含む値の制限があるため、通常は JSON を推奨します。

```text
network(0=unknown,1=KiK-net,2=K-NET),code,suspended(True/False),name,region,latitude,longitude,image_x,image_y,classification_id,prefecture_classification_id,old_latitude,old_longitude
```

## NIED 公式 CSV

1. ツールバーの `NIED 下载` から K-NET と KiK-net をそれぞれダウンロードします。
2. `导入 NIED CSV` で 1 ファイル、または 2 ファイルを同時選択します。新 UI では保存場所・ファイル名の固定は不要です。
3. 従来 UI では EXE と同じディレクトリに `sitepub_knet_sj.csv` と `sitepub_kik_sj.csv` を置き、`导入 → NIED 观测点信息` を使用します。

取得元は [NIED 観測点一覧](https://www.kyoshin.bosai.go.jp/ja/stationlist/) です。サイトのフォームを通して取得するため、固定の CSV URL を直接開く方式ではありません。ネットワーク処理はバックグラウンドで行い、検証済みの元の CSV バイト列を保存します。失敗した場合は既存ファイルを置換しません。

Shift-JIS の現行 11 列・旧 14 列を読み込み、コードで照合して名称・地理情報・休止状態を更新します。既存の画像座標は維持し、旧地理座標が欠けている場合は既存値を維持します。両ファイルを検証してから更新し、途中で失敗した場合は変更を戻します。

**公式 CSV には画像取得座標がありません。** 新規に登録された点には別途画像座標を設定してください。通常の `文件 → 打开` ではなく専用インポートを使います。サイトの仕様が変わった場合は同じメニューから公式ページを開いてください。

## EqWatch インポート

この入口は `--legacy` の従来 UI に残しています。

`v5 Kyoshin Monitor Base Data for EqWatch` 形式の `Kansokuten.dat` をプログラムの**作業ディレクトリ**にコピーし、`导入 → EqWatch 的 Kansokuten.dat` を実行します。EXE のディレクトリを作業ディレクトリとして起動すると分かりやすくなります。

EqWatch は観測点コードを持たないため、ネットワーク・名前・地域で照合します。未一致の点には `_EQW番号` を付けるので、NIED データを先にインポートしてください。名前の表記差（例: `烏海` / `鳥海`）がある場合はコピー側を確認してください。既存の画像座標がある場合は補完モードを選択できます。データの利用条件は EqWatch 作者の指示に従ってください。

## ビルドとテスト

Windows、PowerShell、Visual Studio / Build Tools（.NET デスクトップ用 MSBuild と C# コンパイラー）、原版 0.0.6.0 の配布 DLL が必要です。ターゲットは .NET Framework 4.7 のままです。

```powershell
git clone --recurse-submodules https://github.com/YASJUN/KyoshinShindoPlaceEditor.git
cd KyoshinShindoPlaceEditor
.\Build-Chinese.ps1 -OriginalReleaseDir 'C:\Tools\KyoshinShindoPlaceEditor.0.0.6.0'
```

`OriginalReleaseDir` は原版の DLL がある実際の場所へ変更してください。スクリプトは必要なら NuGet から .NET Framework 4.7 の参照アセンブリと固定バージョンの `Microsoft.Web.WebView2 1.0.4314.35` を取得し、原版 `KyoshinMonitorLib.dll` を参照してビルドします。原版データ処理 DLL の更新や自動デプロイは行いません。従来のライブラリ参照による `MSB3277`（`System.Net.Http`）警告が出る場合があります。

出力は `KyoshinShindoPlaceEditor\bin\Release` です。配布ディレクトリをバックアップしてから、新 EXE、`Microsoft.Web.WebView2.Core.dll`、`Microsoft.Web.WebView2.WinForms.dll`、`Modern`、`runtimes`、`WebView2-LICENSE.txt`、`WebView2-NOTICE.txt` をコピーしてください。原版データ処理 DLL、CSV、JSON、既存の `KyoshinShindoPlaceEditor.exe.config` は維持してください。EXE だけの置換では新 UI は起動しません。

```powershell
.\tests\Test-Editor.ps1 `
  -ReleaseDir 'C:\Tools\KyoshinShindoPlaceEditor.0.0.6.0' `
  -SamplePath 'C:\Data\intensity-points.json'
# 上記に -Network を追加すると NIED の実ダウンロードも検証
.\tests\Test-Editor.ps1 -VisibleOnly
.\tests\Test-ImageResources.ps1
```

サンプル JSON は 1,749 点を含む対応実データを別途用意し、WebView2 Runtime をインストールしてください。テスト用にコピーして使用し、入力ファイル自体は書き換えません。通常の回帰テストは 17 項目、`-Network` 付きは 18 項目です。`-VisibleOnly` は実ウィンドウでの 100 回の選択・拡大縮小、34 回の編集、取り消しと JSON メタデータの保持を検証し、`tests\bin\modern-editor.png` にスクリーンショットを保存します。画像リソースのテストにもネットワーク接続が必要です。

性能は読み込み関数だけでなく、実ウィンドウとメッセージループを含めて検証します。新 UI はネイティブの観測点行を生成せず、表示中の約 30～40 行だけを DOM に保持します。単点編集・単点取り消しは差分通知です。計測方法と採用しなかった方式は [PERF.md](PERF.md) を参照してください。実測値は環境によって変わります。

`ModernEditorForm*.cs` は WebView2 ホスト、制限付きメッセージ処理と画像取得、`Modern/` はローカル UI、`MainForm.ModernModel.cs` は既存の JSON / CSV / 結合 / 履歴処理との接続を担当します。従来 UI とその回帰テストも保持しています。

## 設定と既知の制限

- 既存の `KyoshinShindoPlaceEditor.exe.config` 内の `AutoLoadFilePath` で起動時の読み込み先を指定できます。絶対・相対パスに対応します。
- リアルタイム画像は自動更新ではありません。PC の時刻とネットワーク、配信側の状態によって取得に失敗する場合があります。
- 従来 UI の原版 `退出` メニューはクリック処理が未実装です。終了にはウィンドウの閉じるボタンを使ってください。
- 緯度経度の編集、やり直しは追加していません。地図は内蔵の静的画像で、選択に合わせて表示範囲が追加取得されることはありません。
- 本 fork の変更は原作者による更新ではありません。不具合はこの fork の Issue に、入力形式・操作手順・エラー内容を添えて報告してください。
